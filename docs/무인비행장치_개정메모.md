# 무인비행장치 측량 작업규정 개정 편집기

「무인비행장치 측량 작업규정」
(국토지리정보원고시 제2020-5670호, 10장 40조 · 별표 7)을 고치는 편집기입니다.

- 주소 — `/uav/` (작업규정 편집기는 `/`, 성과심사 규정 편집기는 `/review/`)
- 로컬 실행 — 윗 폴더의 `실행.무인비행장치.bat`, 또는 `python serve.py 8767 uav/`

이 폴더에는 **화면 파일(`index.html`) 하나만** 있습니다.
프로그램(`../js`)과 규정 데이터(`../data`)는 다른 편집기와 한 벌을 함께 씁니다.
`<base href="../">` 로 윗 폴더를 가리키고,
`<meta name="app-profile" content="uav">` 로 “무인비행장치 규정을 고치는 편집기”임을 알립니다.

무엇이 다른지는 `../js/core/appconfig.js` 의 `uav` 프로파일 한 곳에 모여 있습니다.

| | 값 |
|---|---|
| 개정 대상 | 무인비행장치 측량 작업규정 (`data/reg12.json`) |
| 현행 조문 | **법제처 내려받기 원문**(HWPML)에서 읽었습니다 — 아래 참조 |
| 시작 버전 | v1 (2024년 연구성과) · v2 (2025년 연구결과) — `data/draft_uav.json` |
| ② 창 차례 | 영상·점군 성과 규정 4종 → 공공측량 작업규정 → 상위 법령 → … |
| 최상위 계층 | 장 (이 규정에는 편이 없습니다) |
| 부르는 말 | 개정안 |
| AI 일감 | 전부개정 |

## ② 창 첫 묶음을 따로 둔 까닭

무인비행장치 측량은 **항공사진 → 항공삼각측량 → 수치표고모델 → 정사영상 → 수치지형도** 로
이어지는 성과를 만들고, 그 정확도·성과품 기준은 다음 네 규정에 흩어져 있습니다.

| 규정 | 맞물리는 곳 |
|---|---|
| 항공사진측량 작업 및 성과에 관한 규정 (`reg13`) | 촬영·항공삼각측량 기준 |
| 정사영상 제작 작업 및 성과에 관한 규정 (`reg14`) | 정사영상 제작·품질 |
| 수치표고모형의 구축 및 관리 등에 관한 규정 (`reg16`) | 수치표고모델·항공레이저측량 |
| 3차원국토공간정보구축작업규정 (`reg17`) | 3차원 성과·점군 |

이들은 「공공측량 작업규정」이 인용하는 규정이라 기본 가르기로는 `cited` 묶음에 섞입니다.
`appconfig.js` 의 `uav.regroup` 이 이 넷만 `aerial` 묶음으로 당겨 맨 앞에 보입니다.

## 현행 조문은 법제처 원문 파일에서 읽습니다

다른 규정은 국가법령정보센터 공개 API 로 받았지만, 이 규정은 법제처에서 내려받은
고시 원문 파일을 씁니다.

```bash
python scripts/genhwpml.py reg12 "../관련규정/하위규정/무인비행장치 측량 작업규정(국토지리정보원고시)(제2020-5670호)(20201230).hwp"
```

| | 공개 API | 법제처 원문 파일 |
|---|---|---|
| 항·호 줄바꿈 | 한 줄로 뭉쳐 옴 — 추측으로 되살려야 함 | 항과 호가 저마다 한 문단 |
| 본문 그림 | `<img id="…">` 자리표시만 (그림 없음) | 그림이 파일 안에 들어 있음 |
| 부칙 | 없음 | 있음 (편집기에는 넣지 않습니다) |

바꾼 결과 — **40조 모두 글자가 같고**(따옴표·공백 제외), 그중 10조의 줄 구조를
원문대로 되살렸으며, 제13조의 중복도 도해 1개를 `data/objects/reg12/pic1.gif` 로
꺼내 본문에 끼웠습니다. 별표 7건·출처·고시번호는 그대로 두었습니다.

### 관보 원본·국토부 개정 전문과도 대조했습니다

`관련규정\무인비행장치 측량 작업규정개정관련0.무인비행장치 측량 작업규정` 폴더의
국토지리정보원 고시 원본(`2.무인비행장치 측량 작업규정.2020.hwp`, 옛 HWP 이진)과
견주면 **40조가 글자 하나까지 같습니다.** 다른 곳은 가운뎃점 표기뿐입니다.

| | 관보 원본 | 법제처 판 (지금 쓰는 것) |
|---|---|---|
| 가운뎃점 | `ㆍ` (U+318D) — 이ㆍ착륙, 종ㆍ횡단면도 | `·` (U+00B7) — 이·착륙, 종·횡단면도 |
| 그 밖 | — | 다른 차이 없음 (18곳 모두 이 글자) |

윗 폴더의 `국토부.무인비행장치 측량 작업규정.개정 전문.hwp` 도 견주었습니다 —
파일은 다르지만(30,720 B / 55,808 B) **글자는 180줄이 한 줄도 다르지 않습니다.**
이름과 달리 고친 내용이 들어 있지 않은, 2020년 고시 전문(全文) 그대로입니다.

다른 규정 63종도 모두 `·` 로 색인되어 있어 법제처 판을 그대로 둡니다.
다시 견주려면:

```bash
python scripts/genhwpml.py reg12 "../관련규정/무인비행장치 측량 작업규정개정관련/2020.무인비행장치 측량 작업규정/2.무인비행장치 측량 작업규정.2020.hwp" --dry
```

### 별표 7건 — 미리보기 · 서식 표 · 원본 파일

같은 폴더의 별표 원본(HWP·PDF 각 7건)으로 세 가지를 한꺼번에 만듭니다.

```bash
python scripts/genannexlocal.py reg12 "../관련규정/무인비행장치 측량 작업규정개정관련/2020.무인비행장치 측량 작업규정"
```

| 만드는 것 | 자리 |
|---|---|
| 미리보기 (PDF → 쪽 그림) | `data/annex/reg12/별표N_1.webp` — 7쪽 |
| **원본 파일** (내려받기용) | `data/annex/reg12/원본/별표N.hwp` · `.pdf` — 14개 · 692 KB |
| **서식 표 XML** | `data/objects/reg12/annex/별표N.xml` — 표 6개 |
| 표 속 그림 | `data/objects/reg12/annex/별표1_img1~3.webp` — 3개 |

- **원본 내려받기가 앱 안에서 됩니다.** 전에는 별표마다 법제처 주소로 나가는 HWP
  링크 하나뿐이었고 PDF 는 아예 없었습니다. 이제 `annexRef.hwp`·`annexRef.pdf` 가
  앱 안의 파일을 가리키고, 법제처 주소는 `annexRef.source` 에 남겨 두었습니다.
- **별표 1(지상기준점의 배치)은 표가 아니라 그림입니다.** 그래서 표로 바꾸면 빈 칸
  두 개짜리 표만 남았습니다. 이제 HWP 안의 그림 3개(279×274 · 503×170 · 290×42)를
  꺼내 XML 에 `<image>` 로 싣고, 화면에 그림 그대로 보입니다.
  (`js/core/objects.js` 가 `<image>` 를 읽어 그립니다.)
  배치도 두 장(그림 1·2)은 **한 줄에 나란히** 둡니다 — XML 의 `row` 가 같은 그림끼리
  묶고, 넓이는 원본 가로 비(279:503)로 나눕니다. 어느 그림을 한 줄에 둘지는
  `scripts/genannexlocal.py` 의 `ROWS` 에 적습니다.
- 별표 2~7 은 표 1개씩(18~48행) 으로 그대로 바뀝니다. 별표 HWP 는 앞서 법제처에서
  받아 둔 것과 **바이트까지 같습니다**(md5 7건 일치).

### v1 — 2024년 연구성과 (기본측량 성과 적용을 위한 무인비행장치 활용 연구)

근거는 `2024.연구성과.무인비행장치 측량 작업규정.개정안_25.07.18.pdf` 부록 1 의 신구대조표
여섯 마디입니다.

| 조문 | 고친 것 | 근거 쪽 |
|---|---|---|
| 제8조(대공표지) | 준용 규정에 **별표 8** 을 나란히 두고 인용 이름을 지금 이름으로 | 3쪽 |
| 제9조(지상기준점의 배치) | 제3항을 각 호로 — **PPK 쓰면 1㎢당 4점 이상**, 방법은 별표 9 | 4~5쪽 |
| 제10조(지상기준점 측량방법) | 표고기준점측량에 **GNSS 높이측량·지상기준점측량 방법** 을 더함 | 6~7쪽 |
| 제13조(촬영계획) | **1/500 초과 축척의 지상표본거리 표**, 제4항에 **촬영고도 산정식** | 1~2쪽 |
| 제32조(벡터화 묘사) | 허용범위를 각 호로 — 기복변위로 인한 묘사 누락 금지 | 8쪽 |
| 제38조(품질관리) | 제4항 신설 — **별표 10** 에 따라 공정별·최종 품질관리 | 9~10쪽 |

별표 8(대공표지 형상) · 별표 9(GNSS PPK 활용) · 별표 10(품질관리기준)을 신설하고,
근거가 된 PDF 쪽을 미리보기 그림으로 함께 담았습니다(`data/annex/draftUav/`).

신구대조표의 `------` 는 현행 글자를 그대로 둔다는 뜻이므로 **바뀌는 말만 갈아 끼웠고**,
갈아 끼우기 전에 현행 글월이 개정(안)이 적은 것과 같은지 확인합니다(다르면 멈춥니다).
개정(안)이 벡터화 묘사를 '제43조' 로 적었으나 현행은 제32조여서 조 번호는 현행에 맞추었습니다.

### v2 — 2025년 연구결과 (드론 다중센서)

`무인비행장치 측량 작업규정 개정(안).hwpx` 전문을 옮긴 판입니다. 광학영상 중심의 현행
체계를 **드론 다중센서(UAV LiDAR · GNSS/INS · RTK/PPK)** 기반으로 넓혀 10장 42조로
다시 짰습니다 — 신설 16조 · 고침 26조, 별표 15건(현행 7건 수정 + 8건 신설).

- 조문 상태(수정·이동·수정·신설)는 **현행 조문과 제목을 맞대어** 정합니다. 제목이 같은
  조문이 여럿인 경우('성과 등' 은 현행에 여섯 곳) 앞에서부터 하나씩 짝지웁니다.
  짝지어진 조문은 기준의 노드 id 를 물려받아 검증·비교표에서 같은 조문으로 이어집니다.
- 제목까지 바뀌어 짝이 없는 조문은 **조 번호가 같은 현행 조문에 잇습니다**(2벌 짝짓기).
  현행 제13조(촬영계획) ↔ v2 제13조(촬영 및 스캔계획)처럼 제목만 바뀐 것이 12건이며,
  잇지 않으면 한 조문이 '삭제 + 신설' 두 건으로 잡혀 비교표가 부풀어 오릅니다.
  이렇게 이은 조문은 사유의 **○ 개정 내용** 에 `제목이 '…' 에서 '…' 로 바뀌었다 — 조 번호가
  같아 현행 조문에 이어 붙였으니 같은 조문으로 볼지 확인이 필요하다` 가 붙습니다.

  | 이어 붙인 것 | |
  |---|---|
  | 제13조 촬영계획 → 촬영 및 스캔계획 | 제14조 촬영비행 및 촬영 → 촬영비행 및 레이저측량 스캔 |
  | 제15조 재촬영 → 재촬영 및 재스캔 | 제20조 수치표면자료의 생성 → 레이저측량 점군자료의 생성 |
  | 제21조 수치지면자료의 제작 → 레이저측량 궤적처리 및 블록 조정 | 제22조 수치표면모형·수치표고모형의 제작 → 점군분류 및 수치지면자료 제작 |
  | 제23조 정확도 점검 → DSM, DTM 또는 DEM의 제작 | 제28조 정사영상의 정확도 → 다중센서 정합 |
  | 제29조 성과 등 → 정사영상의 정확도 및 성과 | 제30조 묘사 → 지형·지물 묘사 |
  | 제32조 벡터화에 의한 지형·지물의 묘사 → 객체기반 갱신자료 제작 | 제39조 정리점검 → 성과품의 표준 포맷 |

  이어 붙인 뒤 **신설 16 → 4 · 고침 26 → 38**, 검증의 '사라진 조문' 은 14건 → **2건**
  (현행 제27조 보안지역 처리 · 제33조 성과 등)으로 줄었습니다.
- 조문마다 `개정사유서.hwpx` 의 **4. 조항별 개정 사유**, 별표마다 **5. 별표 개정 및 신설 사유**
  를 사유로 답니다.
- 별표 본문은 `별표수정(안).hwpx` 의 표를 글로 옮긴 것이라 칸 구분이 성글 수 있습니다.
  서식으로 옮길 때 원본을 함께 보십시오.
- 부칙 3조는 다른 규정 63종과 마찬가지로 싣지 않았습니다.

옛 이름 넷 — 「항공사진측량 작업규정」→「항공사진측량 작업 및 성과에 관한 규정」,

「항공레이저측량 작업규정」→「수치표고모형의 구축 및 관리 등에 관한 규정」,
「수치지형도 작성 작업규정」→「수치지형도 작성 작업 및 성과에 관한 규정」.

`UAV LiDAR` 는 한 낱말로 보아 UAV 규칙보다 앞에서 바꿉니다 — 먼저 UAV 를 바꾸면
'무인비행장치 LiDAR' 가 되므로 그 꼴도 함께 받고, 그 뒤에 홀로 쓰인 `LiDAR` 를
바꿉니다. 차례가 뒤바뀌면 'UAV 레이저측량' 이 되어 버립니다. 바꾼 뒤 v2 에는
`LiDAR` 가 한 곳도 남지 않고 '레이저측량 레이저측량' 처럼 겹친 곳도 없습니다.

용어 손질이 있으면 **상태와 상관없이 '용어' 로 표시**합니다 — 개정으로 이미 고쳐지는
조문(수정·신설)이라도 편집기 아래쪽 [용어] 골라 보기로 함께 걸러 볼 수 있습니다
(v1 21건 · v2 34건 조문, 별표를 넣으면 25·49건). 공청회에서 다툴 것과 다투지 아니할
것을 가르기 위함입니다.

- 말만 바뀐 조문 — 상태가 **유지 → 수정**으로 바뀌고, 사유에 용어 정비 다섯 마디가 붙습니다.
- 이미 고쳐지는 조문 — 상태는 그대로 두고, 사유의 **○ 개정 내용** 끝에 한 줄만 보탭니다
  (`* 함께 용어를 손질했다 — 드론·UAV → 무인비행장치, …`).

「항공안전법」·「항공안전법 시행규칙」·「항공사업법」은 우리 자료에 색인되어 있지 않아
참조규정 창에서 열리지 않습니다. 넣으려면 `scripts/gendata.py` 의 `TARGETS` 끝에 더해
다시 받으십시오.

### 변경 사유는 작업규정 편집기와 같은 다섯 마디로

```
[변경 사유]

○ 현행 규정:      ○ 현행의 문제:      ○ 관련 근거:      ○ 개정 사유:      ○ 개정 내용:
```

`draft2025`(작업규정 편집기)와 마디 이름·빈 줄 자리를 똑같이 맞추었습니다. **관련 근거에는
파일 이름이 아니라 그 자료에서 찾은 내용**을 싣습니다 — 이를테면 제13조에는 일본 작업규정의
지상표본거리 기준(지도정보레벨 250 → 0.02m)과 ASPRS 권장안(RMSEH 2.5cm → 화소 1.25~2.5cm)
이, 제9조에는 PPK 정확도 평가(4점 10cm · 1~3점 24cm · 단독 32cm)가 들어갑니다. 출처는 그
마디 끝에 한 줄로 붙습니다.

고시 원문은 표를 그림 한 장으로 넣어 두었습니다. 그림은 글자를 고를 수도, 견줄 수도,
비교표에 실을 수도 없어 표로 옮겼습니다.

| 자리 | 무엇 | 어떻게 |
|---|---|---|
| 기준(현행) 제13조제2항 | 촬영 중복도 표 (그림 `pic1.gif`) | `objects/reg12/t13ovl.xml` 3행 4열 — `python scripts/genbodyxml_uav.py` |

| v2 제13조제2항 | 개정(안)의 중복도 표 | `objects/reg12/t2v1.xml` — 개정(안) HWPX 의 표를 그대로 |

원본 그림은 지우지 않고 `objects/reg12/pic1.gif` 로 남겨 두어 옮긴 표와 견줄 수 있습니다.
개정(안) HWPX 의 표는 예전에 칸이 글줄로 풀어져 본문에 두 번 박혔는데, 이제 섹션 바로

### 별표를 부르는 조문

개정(안)은 별표 15건을 두었으나 본문이 별표 2~15 를 부르지 않아, 어느 조문의 서식인지
규정만으로는 알 수 없었습니다. 현행 규정이 하던 대로 **성과 정리 호 뒤에 `<별표 N>` 를
달고**, 그 자리가 없는 신설 별표는 **그 별표를 만들어 내는 공정 조문에 항을 하나 더** 두었습니다

### 바뀐 말은 푸르게

고친 조문에는 현행 본문을 함께 담아 두어(`wasBody`), 조문 상세의 **현행과 달라진 곳**
칸에서 바뀐 말이 **푸른 밑줄**로 드러납니다. 별표는 이름이 바뀐 것을 붉게 짚습니다
(`wasTitle`). 개정안·성과심사 편집기와 같은 방식입니다.

## 알아 둘 것

- **[현행으로 초기화] 를 누르면 v1·v2 초안이 사라집니다.** 자동 저장이 그 상태를 담아
  두어 다시 열어도 돌아오지 않습니다. 초안을 되찾으려면 브라우저 저장소(IndexedDB
  `pmproj`)를 비우고 새로 고치십시오.
- **현행 제3조가 옛 규정 이름을 준용하고 있습니다.** 개정 때 함께 고쳐야 합니다.

  | 제3조가 쓴 이름 | 지금 이름 |
  |---|---|
  | 항공사진측량 작업규정 | 항공사진측량 작업 및 성과에 관한 규정 (`reg13`) |
  | 영상지도제작에 관한 작업규정 | 정사영상 제작 작업 및 성과에 관한 규정 (`reg14`) |
  | 항공레이저측량 작업규정 | 수치표고모형의 구축 및 관리 등에 관한 규정 (`reg16`) |
  | 수치지형도 작성 작업규정 | 수치지형도 작성 작업 및 성과에 관한 규정 (`reg15`) |

- **「항공안전법」계열은 아직 색인되어 있지 않습니다.** 비행 승인·안전 조항을 손보려면
  `scripts/gendata.py` 의 `TARGETS` **끝에** 한 줄을 더하고 다시 받으십시오
  (`("항공안전법", "항공안전법", "law", "law")`). 중간에 끼워 넣으면 `regNN` 번호가
  밀려 `appconfig.js` 의 `AERIAL` 목록과 인용 표시가 어긋납니다.
- 초안(`data/draft_*.json`)이 없으므로 v1 이 처음부터 **편집 가능**합니다.
  (작업규정·성과심사 편집기의 v1 은 연구보고서 초안이라 읽기 전용입니다.)
