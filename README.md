# 공공측량 규정 개정 편집기 — 프로토타입

개정 대상 **세 규정을 한 트리에 나란히 놓고**, 조항을 마우스로 끌어 옮기며
새 편제를 설계·편집·저장하는 도구입니다.

| 개정 대상 | 개정안 본문 | 부속 |
|---|---|---|
| 「공공측량 작업규정」 | 7편 32장 234조 | 별표 57 · 별지 5 |
| 「측량성과 심사수탁기관의 심사업무 및 지정절차 등에 관한 규정」 | 6장 5절 54조 | 별표 17 · 별지 6 |
| 「무인비행장치 측량 작업규정」 | 10장 42조 | 별표 15 |

UI 설계안 v3 의 **1단계(합치기)** 를 마쳤습니다 — 세 벌로 갈라져 있던 편집기가 한 벌이 되었습니다.

## 실행 방법

`실행.bat` 을 더블클릭하면 로컬 서버가 뜨고 브라우저가 열립니다.
(창을 닫으면 서버가 종료됩니다.)

직접 실행하려면 이 폴더에서:

```bash
python serve.py 8765
```

그리고 브라우저에서 `http://127.0.0.1:8765/` 를 엽니다.
(`serve.py` 는 브라우저 캐시를 끈 정적 서버입니다. 예전 화면이 계속 보이면 `Ctrl+Shift+R`.)

편집기는 **한 벌**입니다. 개정 대상 세 규정은 오른쪽 트리 최상위에 나란히 서 있고,
줄을 눌러 오갑니다 — 예전처럼 주소를 갈아탈 일이 없습니다.

> **파일을 직접 더블클릭(file://)하면 동작하지 않습니다.**
> 브라우저 보안 정책상 ES 모듈과 파일 저장 기능이 `localhost` 에서만 허용됩니다.
> 권장 브라우저는 **Chrome 또는 Edge** 입니다 (파일 덮어쓰기 저장 지원).

## 개정 대상 세 규정 — 한 트리에 나란히

편집기는 한 벌이고, 고치는 규정 셋이 트리 최상위에 나란히 섭니다.

```
③ 개정안 구조
   ▾ 공공측량 작업규정                    7편 32장 234조
       ▸ 제1편 총칙
       ▸ 제4편 3차원 공간정보 구축
   ▸ 측량성과 심사수탁기관 규정            6장 5절 54조
   ▸ 무인비행장치 측량 작업규정            10장 42조
```

트리에서 조문을 고르면 **왼쪽 두 창이 그 규정을 따라옵니다.**

| 고른 규정 | ① 현행규정 창 | ② 참조규정 첫 묶음 | 최상위 단 | 부르는 말 |
|---|---|---|---|---|
| 작업규정 | 공공측량 작업규정 | 규정 내 별도규정(인용) | **편** | 개정안 |
| 성과심사 | 측량성과 심사수탁기관 규정 | 성과심사 관련규정 12종 | 장 | 개정안 |
| 무인비행장치 | 무인비행장치 측량 작업규정 | 영상·점군 성과 규정 4종 | 장 | 개정안 |

### 무엇을 고치는가는 데이터가 정한다

개정 대상은 **`data/targets.json` 등록부** 한 곳에 적혀 있습니다.
규정을 하나 더 올리려면 등록부에 줄 하나를 더하면 됩니다 — 화면 파일도 주소도 늘지 않습니다.
(예전에는 `js/core/appconfig.js` 의 프로파일을 더하고 화면 파일을 한 벌 복사해야 했습니다.)

규정 경계를 아는 곳은 **`js/core/targets.js` 한 곳**입니다.
어느 조문이 어느 규정 것인지 묻는 물음의 답은 여기에서만 냅니다.

### 조 번호와 조문 id

- **조 번호는 규정마다 1부터** 다시 매깁니다. 세 규정을 통틀어 1‥330 으로 매기지 않습니다.
- **조문 id 에 규정 이름표를 붙입니다** (`work:a3` · `uav:a3`).
  규정마다 따로 매겨져 있어 `a3` · `a7` · `a22` 같은 id 가 세 규정 모두에 있었습니다.
  이름표가 없으면 조문을 고를 때 엉뚱한 규정의 조문이 잡힙니다.
- **읽기 전용은 규정마다 다릅니다.** 작업규정·성과심사 초안은 읽기 전용이고
  (고치려면 `⑂분기`), 무인비행장치 초안은 곧바로 고칩니다.
  이 차이를 잃지 않도록 잠금을 판(버전)이 아니라 규정 노드에 붙였습니다.

### 세 벌 시절 작업 옮겨 담기

편집기가 셋일 때에는 브라우저에 `project:work` · `project:review` · `project:uav` 로
따로 담겼습니다. 합친 뒤 처음 켤 때 그 셋을 한 자리(`project:all`)로 **한 번만 옮겨 담습니다.**
옮긴 작업은 `이어받음` 판으로 서고, **원본은 지우지 않습니다** — 되돌릴 수 있게 남겨 둡니다.

## 파일 열기 → 색인화 → 한글 대역

참조 규정 창의 **[파일 열기]** 로 `관련규정` 폴더의 파일을 직접 불러와 조문 트리로 만듭니다.

| 형식 | 처리 |
|---|---|
| `.pdf` | 내장 pdf.js 로 텍스트 추출 (189쪽 약 2초) |
| `.hwpx` | ZIP 해제 후 본문 XML 파싱 |
| `.hwp` | 국가법령정보센터 내려받기 파일(HWPML/XML)은 바로 열림 |
| `.txt` `.md` | 그대로 |
| `.json` | 이 앱이 만든 조문 트리 |

> 구형 이진 HWP(한/글에서 만든 일반 문서)는 열리지 않습니다.
> 한/글에서 **다른 이름으로 저장 → HWPX** 로 바꾼 뒤 열어 주세요.

**색인화** — 문서를 보고 두 가지 방식 중 알아서 고릅니다.

| 방식 | 대상 | 인식하는 표제 |
|---|---|---|
| **조문 체계** | 국내 고시·법령, 일본 준칙 | `제N편/장/절/관/조`, `第N編/章/節/条` (전각 숫자, 제목이 앞 줄 괄호에 있는 형식 포함), `부록·附録·별첨` |
| **목차 체계** | ASPRS·USGS·FGDC 등 조문 없는 국외 기준 | `1.` `1.2` `1.2.3` 번호 매김, `Appendix/Annex`, `Chapter/Section/Part` |

목차 체계는 번호의 점(.) 개수로 깊이를 정하고, 표제 사이의 글을 본문으로 붙입니다.
두 방식 모두 **앞머리 목차와 부칙을 자동으로 걷어냅니다**(목차 항목이 본문에서 되풀이될 때만).

**별표·부록** — 국내 규정 32종의 별표·서식 462건이 본문 트리 뒤에 `별표 (N건)` 가지로 붙습니다.
항목을 고르면 조문 상세에서 원본 **HWP·PDF 를 바로 내려받을** 수 있습니다.
문서 안에 `부록`·`附録`·`별첨` 이 있으면 최상위 항목으로 세웁니다.

실측 결과:

| 파일 | 색인 결과 | 실제 |
|---|---|---|
| 공공측량 작업규정 (HWPX) | 5편 24장 218조 | 5편 24장 217조 |
| 무인비행장치 측량 작업규정 (HWP) | 10장 40조 | 40조 |
| 일본 作業規程の準則 (PDF 189쪽) | 5편 26장 148절 715조 | 715조 |
| ASPRS 형식 (목차 체계) | 1단 3 · 2단 3 · 3단 1, 각 항목에 본문 부착 | — |

**한글 대역** — 일본어·영어 문서는 불러올 때 한글 대역을 자동 생성합니다.
`표시` 단추로 **원문 / 번역 / 대역(두 줄)** 을 바꿔 볼 수 있고, 조문 상세에도 원문과 대역이 함께 뜹니다.
**한글로 검색해도 일본어 원문 문서에서 조문을 찾습니다.**

**프로젝트에 함께 저장** — 불러온 규정은 조문 트리·한글 대역까지 `.pmproj` 안에 들어갑니다.
다음에 프로젝트를 열면 참조 창의 규정과 표시 모드까지 그대로 복원됩니다.
더 이상 필요 없으면 규정 선택 옆 `−` 로 프로젝트에서 뺄 수 있습니다(파일 용량이 줄어듭니다).

> **이것은 기계번역이 아니라 측량 분야 용어 대응표(285개) 기반 치환입니다.**
> 편·장·절 표제와 조문 제목은 대체로 그대로 쓸 수 있는 수준이고(`測量標の設置 → 측량표 설치`,
> `基盤地図情報 → 기반지도정보`), 본문은 어순이 일본어로 남아 **뜻 파악용**입니다.
> 일본 준칙 기준 치환률은 약 66% 입니다. 원문은 항상 보존되며, 외부 번역 API 를 붙이려면
> `js/core/translate.js` 의 `translateVia()` 하나만 교체하면 됩니다.

## 조문 검색

참조 창과 가운데 편집 창 모두 검색창이 있습니다.

- 입력하면 적중 항목이 노랗게 표시되고 **첫 결과로 바로 이동**합니다.
- `Enter` 다음 결과, `Shift+Enter` 이전 결과, `‹` `›` 단추도 같습니다.
- 이동하면 상위 편·장이 자동으로 펼쳐지고 해당 줄이 화면 가운데로 오며,
  **오른쪽 조문 상세 칸에 그 조문이 표시됩니다.**
- 검색 범위: 조 번호 · 제목 · 본문 · 한글 대역 · 현행 조번호.

## 참조 규정 창 2개

왼쪽 열이 위아래 두 칸으로 나뉘어 있고, 각 칸이 **서로 다른 규정**을 독립적으로 띄웁니다.
규정 선택·검색·접힘 상태가 칸마다 따로 놀기 때문에, 예를 들어 위에는 일본 준칙,
아래에는 현행 공공측량 작업규정을 놓고 대조하며 작업할 수 있습니다.

- 처음 열 때 ①은 국가기준점측량 작업규정, ②는 현행 공공측량 작업규정으로 시작합니다.
- 두 창 어디에서든 노드를 가운데 트리로 끌면 복제 삽입되고, 어느 규정에서 왔는지 출처가 기록됩니다.
- ② 창 머리의 `✕` 로 닫고, ① 창 머리의 `＋` 로 다시 엽니다.
- 두 창 사이 경계선을 위아래로 끌어 높이를 조절합니다.

### 참조 ① ↔ ② 조문 비교

**두 창에서 각각 조문을 하나씩 고르면** 조문 상세가 자동으로 비교 화면으로 바뀝니다.

- 제목과 본문을 ①/② 로 나란히 놓고, **다른 낱말에 밑줄**을 칩니다.
  왼쪽 밑줄은 ①에만, 오른쪽 밑줄은 ②에만 있는 표현입니다.
- 한글 대역이 있는 문서는 대역문끼리 비교하므로, 일본 준칙과 현행 규정을 바로 견줄 수 있습니다.
- **같은 항목을 다시 누르면** 그 창의 선택이 풀리고, 남은 한쪽만 읽기 전용으로 보여 줍니다.
  둘 다 풀면 가운데 개정안의 선택으로 돌아갑니다.
- 상세 창이 좁으면 ①/② 가 위아래로 쌓입니다. 창 경계선을 끌어 넓히면 좌우로 붙습니다.

### 파일 저장에 이어 저장소에도 올리기

**[저장]** 을 누르면 `.pmproj` 파일로 저장한 뒤, **이미 저장소에 올려 둔 프로젝트라면** 같은 내용을
공유 저장소에도 이어서 올립니다. 저장 메시지는 묻지 않고 `파일 저장에 이어 올림 (이름)` 으로 커밋합니다.

- **처음 올리는 프로젝트는 자동으로 올리지 않습니다.** [공유 저장소] → [새로 저장] 에서
  이름을 정해 한 번 올리고 나면, 그 뒤부터 [저장]에 딸려 갑니다.
- [공유 저장소] → [연결 설정] 의 **"파일로 저장할 때 공유 저장소에도 함께 올리기"** 로 끌 수 있습니다.
- 다른 사람이 먼저 저장해 충돌하면 파일 저장은 그대로 두고 알려 줍니다.

### 불러온 규정을 서버에 올려 함께 쓰기

파일에서 색인한 규정은 그 사람 브라우저에만 있습니다.
저장소를 연결해 두면 창 머리의 **[↥ 공유]** 로 올려 팀 전체가 쓸 수 있습니다.

- 올린 규정은 `<프로젝트 폴더>/refs/<이름>.json` 으로 커밋됩니다.
- 다른 사람의 규정 목록 맨 위에 **공유 규정 (N)** 묶음으로 나타나고, 고르면 바로 내려받아 열립니다.
- 같은 이름으로 다시 올리면 갱신(새 커밋)되므로, 색인을 고친 뒤 다시 올리면 됩니다.
- 저장소를 연결하기 전에는 `[↥ 공유]` 단추가 보이지 않습니다. 메뉴바 **[공유 저장소]** 에서 먼저 연결하세요.

### 신설 조문 48건의 조문안

보고서 본문에서 근거를 찾아 조문안까지 썼습니다. 보고서가 수치를 밝힌 것은 그대로 옮겼고,
"별표로 정한다"까지만 말한 것은 조문에서도 별표로 미뤘습니다. **보고서에 없는 수치는 지어내지 않았습니다.**
보고서가 방향만 짚은 분야는 이미 있는 규정과 일본 준칙에서 수치를 가져오고 그 출처를 사유에 밝혔습니다.

- 점밀도 기본 4 / 고정밀 8 / 초고정밀 20 pts/m², 지면 분류 정확도 95% 이상 (제4장 3)
- 신뢰구간 환산 평면 1.7308 · 수직 1.9600 (부록4 A-6)
- 도통테스트 판정 6구분(정상도통·부분도통·미도통·오접속 의심·불확정·적용불가)과
  성과품 8종, 활선 시설 사전 승인 의무 (제4장 3)
- KS X ISO 19157-1(= ISO 19157-1:2023, IDT) 품질요소 5종, ISO 17123 성능검사 준용 (원칙 5, 부록4 A-4)
- 차량기반 이동측량(MMS) 5개 조 — 아래 절 참조

### 차량기반 이동측량(MMS) — 제4편 제4장

그 장에는 **정밀도로지도 제작** 조문 하나뿐이었습니다. 그것도 「정밀도로지도의 구축 및 갱신
등에 관한 규정」으로 **미루는 위임 조문**이라, 정밀도로지도가 아닌 공공측량에 이동측량을 쓰면
기댈 데가 없었습니다. 이동측량 일반에 공통으로 걸리는 것만 다섯 조로 세웠습니다.

| 조 | 무엇을 정하는가 |
|---|---|
| 제107조 차량기반 이동측량 | 자리매김·적용 범위·준용 관계 |
| 제108조 이동측량시스템의 검정 | 센서 사이의 상대 위치·자세, 검정 유효기간, 시험측량 |
| 제109조 주행 취득 | 누락 없는 취득, 상·하행 중심차로, 폐색 구간 반복, 동기화 |
| 제110조 위성항법 음영구간과 조정점 | 조정점의 수·배치 차례·정확도, 조정처리가 필요한 구간 |
| 제111조 취득 성과의 점검과 정합 | 점검 항목, 중복 영역 정합, 검증점 검증, 성과패키지 |
| 제112조 정밀도로지도 제작 | *(현행 제215조를 옮긴 것 — 별도 규정으로 미룸. 없는 이름이던 「정밀도로지도 제작 작업규정」 인용을 현행 규정명으로 바로잡음)* |

**수치는 지어내지 않고 출처를 사유에 밝혔습니다.**

| 수치 | 출처 |
|---|---|
| 검정 유효기간 — 고정식 1년 · 착탈식 6개월 | 일본 준칙 제492조 |
| 조정점 2점 이상, 배치 차례(음영구간 → 진로 변동 → 시·종점) | 일본 준칙 제496조 |
| 조정점 정확도 표준편차 0.1 m, 점간거리 허용범위 1/10,000(500 m 이상)·50 mm(500 m 미만) | 일본 준칙 제497조 |
| 조정처리가 필요한 구간 | 일본 준칙 제507조제3항 |
| 상·하행 중심차로 주행, 3개 차로마다 1회, 폐색 구간 반복 취득 | 「정밀도로지도의 구축 및 갱신 등에 관한 규정」 제14조 |
| 중복 영역의 정합 검증 | 같은 규정 제21조 |
| 점밀도 등급 | 이 편 통칙(제103조)을 그대로 씀 |

**일부러 쓰지 않은 것도 있습니다.** *차로 중심선의 정확도*와 *객체의 속성체계*는 그 규정
제23조·제24조와 정밀도로지도 데이터 모델 기관표준이 이미 정하고 있어, 여기에 새로 적으면
충돌합니다. 그 판단은 장의 변경 사유에 적어 두었습니다. 정밀도로지도의 1 ㎡당 400점도
그 용도에만 걸리는 기준이라 이동측량 일반의 기준으로 옮기지 않았습니다.

정합 정확도의 성분별 허용범위와 검증점 배치는 **별표 37** 로 미뤘습니다.

### 품관원 검토의견 반영

`품관원.이한.작업규정 변경(안)-2026.07.27_검토의견.hwpx` 의 세부 검토표 16건을 조문에 붙였습니다.
현행 제27·29·32·33·55·70조와 제2편 제4장에 `[품관원] …` 으로 시작하는 사유가 달립니다.

> [품관원] 독립 초기화 후 2세트 이상 관측하고 세트 간 교차기준을 규정
> (검토의견 4: 네트워크 RTK와 같이 반복관측 필요, 우선순위 상)

검토의견이 **직접 짚지 않은 조문에도** 같은 갈래의 지적은 함께 맞췄습니다.
MMS 조문안이 그 예입니다 — 16건 가운데 이동측량을 짚은 것은 없지만, 되풀이되는 두 갈래를
새 조문에도 적용했습니다.

- **점의 종류를 구분해 정의하고 명칭을 통일하라 (검토의견 12·14)** — 총칙은 `검증점` 을
  정의해 두고 제4편은 `검사점` 이라 부르고 있었습니다. 제104·106·111조와 별표 37 제목을
  `검증점` 으로 맞추고, 쓰기만 하고 뜻이 없던 `조정점` 은 제110조에서 뜻을 밝혀 총칙 정의로
  올렸습니다. 이제 **조정점은 성과의 산정에 쓰고, 검증점은 산정에 쓰지 않습니다.**
- **성분별 허용오차를 분리하고 적용대상을 밝히라 (검토의견 13·16)** — 정합 정확도는
  수평·수직 성분으로, 검증점 판정은 수평위치와 표고로 나누어 판정하게 했습니다.

**기준(현행)** 과 **v1. 개정안 초안(2025)** 은 모두 읽기 전용입니다.

## 버전 관리

메뉴바 **[버전 관리]**, 또는 툴바 **[⑂ 새 버전으로 분기]** / `Ctrl+Shift+V`.
오른쪽 위 드롭다운으로 편집할 버전을 바로 바꿀 수 있습니다.

규정을 불러오면 버전이 두 개 만들어집니다.

- **기준** — 현행 원문. 읽기 전용이며 삭제할 수 없습니다. 편집을 시도하면 거부됩니다.
- **v1** — 개정안 초안. 여기서부터 편집합니다.

**분기** — 현재 버전을 통째로 복제해 새 버전을 만들고 그 버전으로 넘어갑니다.
같은 부모에서 여러 갈래를 만들 수 있어(v1 → v2, v1 → v3) 대안을 병행 검토할 수 있습니다.
버전 관리 화면에 계보가 트리로 표시됩니다.

**격리** — 버전끼리 트리를 공유하지 않습니다. v2 에서 조문을 고쳐도 v1 은 그대로입니다.
되돌리기 이력도 버전별로 따로 쌓입니다.

**삭제** — 기준 버전과 마지막 남은 개정안은 삭제할 수 없습니다.
삭제된 버전의 자식은 그 부모로 다시 연결됩니다.

모든 버전은 하나의 `.pmproj` 파일에 함께 저장됩니다.

## 개정 전후 비교표

메뉴바의 **[개정 전후 비교표]** 또는 `Ctrl+D`.

**비교할 두 버전을 자유롭게 고릅니다.** 기준↔v2 뿐 아니라 v1↔v2, v2↔v3 처럼
개정안끼리도 비교할 수 있어 대안 검토에 그대로 씁니다. `⇄` 로 앞뒤를 바꿉니다.

대응 관계는 조문의 내부 ID로 판정하므로, 조 번호가 바뀌거나 다른 편으로 옮겨져도 같은 조문으로 추적됩니다.

**구분 판정**

| 구분 | 판정 기준 |
|---|---|
| 신설 | 개정안에만 있는 항목 (참조 규정에서 인용한 것 포함) |
| 삭제 | 현행에만 있는 항목 — 원래 위치 근처에 끼워 표시 |
| 이동 | 상위 편제가 바뀜 (내용은 그대로) |
| 이동·수정 | 편제도 바뀌고 내용도 바뀜 |
| 수정 | 제목 또는 본문이 바뀜 |
| 유지 | 변화 없음 (조 번호만 밀린 경우 포함) |

**변경 표시** — 제목·본문을 어절 단위로 비교해, 개정 전 칸에는 없어진 어절, 개정 후 칸에는
새로 들어온 어절에 <u>밑줄과 색</u>을 넣습니다. 엑셀로 내보낼 때도 셀 안 서식으로 유지됩니다.

**필터**

- `변경된 항목만` (기본 켜짐)
- `조문만` — 편·장 헤더 행 제외
- `내용 변경 없는 이동 제외` — 편제 재배치로 위치만 바뀐 항목을 숨겨 실질 개정 사항만 남김

**내보내기**

- **엑셀(.xlsx)** — 외부 라이브러리 없이 직접 생성. 열 너비·틀 고정·자동 줄바꿈·변경 어절 밑줄 포함
- **HTML** — 한/글이나 워드에 붙여넣기 좋은 A4 가로 표
- **인쇄** — 브라우저 인쇄 대화상자 (A4 가로)

비고란에는 조번호 변경(`제6장 → 제5편`), 위치 변경 경로, 참조 규정 출처, 입력한 변경 사유가 함께 들어갑니다.

## AI 도우미 (Ctrl+I)

가운데 창 툴바의 **[✦AI]** 로 엽니다. 다섯 가지 일을 시킬 수 있습니다.

| 기능 | 하는 일 | 대상 |
|---|---|---|
| 조문 다듬기 | 제목·본문을 법령 문장 규칙에 맞게 고친 안 + 개정 사유 | 고른 조문 |
| 구조 개편 제안 | 편·장 하위 구조의 이동·통합·신설안 | 고른 편·장 |
| 참조 규정과 견주기 | ② 창 규정과 견주어 빠진 것·다른 것 | 규정 전체 |
| 중복·상충 검토 | 겹치거나 어긋나는 조문 짝 | 규정 전체 |
| 개정 사유 초안 | 이미 바뀐 조문들의 사유 문장을 한꺼번에 | 상태가 '유지'가 아닌 조문 |
| **직접 묻기** | 묻고 싶은 것을 직접 쓰고, 함께 보낼 자료를 골라 보냄 | 고른 자료 |

- **AI 가 내는 것은 언제나 제안입니다.** 화면에서 확인하고 [적용] 을 눌러야 트리에 들어가고,
  들어간 뒤에는 여느 편집과 똑같이 `Ctrl+Z` 로 되돌릴 수 있습니다.
- 조문 다듬기는 **지금 / 제안**을 나란히 보여 주고, 무엇을 왜 고쳤는지와 함께 살필 점을 적어 줍니다.
- 개정 사유 초안은 **이미 사유를 적어 둔 조문은 건드리지 않습니다.**
- 다섯 가지 작업 화면 아래에는 **덧붙일 지시** 칸이 있습니다.
  "문장을 더 짧게", "제3항은 그대로 두고" 처럼 적으면 그대로 따릅니다. 작업을 바꿔도 지워지지 않습니다.
- **직접 묻기**는 물음을 자유롭게 쓰고, 함께 보낼 자료를
  (고른 항목 / 그 하위 구조 / 전체 편제 / 참조 ② 규정) 체크로 고릅니다. `Ctrl+Enter` 로 바로 보냅니다.

### 화면 파일의 캐시 꼬리표

`index.html` 과 `js/` 의 모든 `import` 에 `?v=…` 꼬리표가 붙어 있습니다.
**하나만 갈면 안 됩니다** — 브라우저가 나머지를 옛것으로 가져다 써, 고친 것이
화면에 나타나지 않습니다. 반드시 한꺼번에 갈아 주십시오.

```bash
python scripts/bumpver.py          # 오늘 날짜로 새 꼬리표
python scripts/bumpver.py --check  # 섞여 있지 않은지 확인
```

### 데스크톱 전환을 염두에 둔 두 가지 규칙

1. **바깥과 닿는 곳은 `adapters/` 뿐입니다.**
   Electron 전환 시 이 파일을 Node `fs` 기반 구현으로 바꾸면 나머지는 그대로입니다.
2. **`core/` 는 DOM 을 전혀 참조하지 않습니다.**
   상태는 순수 트리 JSON 이고 렌더링과 분리되어 있어, 화면 기술이 바뀌어도 로직은 유지됩니다.
3. **규정 경계는 `core/targets.js` 한 곳에서만 압니다.**
   어느 조문이 어느 규정 것인지 묻는 자리를 흩어 놓으면 합친 보람이 없습니다.

## 변경 이력

**조문 상세 아래쪽**에 그 조문의 변경 이력이 시간 역순으로 쌓입니다.
언제·무슨 유형(신설/이동/순서/수정/참조삽입/상태변경/삭제/되돌림/다시실행)·무엇을·누가 했는지 한 줄씩 남습니다.
편·장을 옮기면 딸려간 하위 조문에도 `(상위 항목과 함께)` 표시로 함께 기록됩니다.

이력은 각 버전의 **불변 이벤트 원장**에도 함께 기록됩니다. 따라서 조문을 삭제하여 트리에서 사라져도
삭제 시각·원래 조번호·위치·작성자가 남으며, 되돌리기와 다시 실행도 별도 감사 기록으로 보존됩니다.
새 버전으로 분기하면 분기 시점까지의 이력을 상속하고 이후 이력은 버전별로 분리됩니다.

**메뉴바 [변경 이력]** 또는 `Ctrl+H` 로 버전 전체 이력을 봅니다.
유형별 칩으로 거르고, 조문·내용·작성자로 검색하고, 줄을 누르면 해당 조문으로 이동합니다.
CSV 로 내보낼 수 있습니다.

개발 검증은 `node scripts/history_test.mjs` 로 실행할 수 있습니다.

**상태 자동 표시** — 드래그·승격·강등으로 편제가 바뀌면 조문 상세의 `상태` 가 자동으로 **이동** 이 되고,
내용까지 고치면 **이동·수정** 이 됩니다. 트리에도 같은 배지가 붙고, 개정 전후 비교표의 구분과 일치합니다.
(같은 부모 안에서 순서만 바꾼 경우는 이력에 `순서` 로만 남고 상태는 유지됩니다.)

## 별표·별지 개정

별표·별지가 **개정안 트리 맨 아래**에 `별표 (57건)` · `별지 (5건)` 처럼 묶음으로 들어 있습니다.
조문과 똑같이 고르고 고칠 수 있습니다.

- 별표를 고르면 조문 상세에 **제목 · 내용 · 상태 · 변경 사유** 와
  **HWP·PDF 내려받기**, **PDF 통째 미리보기**가 함께 나옵니다.
- 순서를 바꾸면 `별표 1,2,3…` 이 자동으로 다시 매겨집니다. 별지는 별지끼리 따로 셉니다.
  미리보기 그림은 **현행 번호**로 찾으므로 순서를 바꿔도 어긋나지 않습니다.
- 별표는 별표 묶음 안에서만 옮길 수 있고, 묶음을 고른 채 `＋ 하위 신설` 을 누르면 새 별표가 생깁니다.
- 조문 통계와 개정 전후 비교표에서 조와 별표·별지를 따로 셉니다.

### 별표·별지 110건 모두 내려받기와 미리보기

세 개정안의 별표·별지 **110건이 빠짐없이** HWP 와 PDF 를 갖추고 있고,
미리보기는 한 쪽 그림이 아니라 **PDF 파일 전체**를 띄웁니다.

| 어디서 온 것 | 몇 건 | 두는 곳 |
|---|---|---|
| 국가법령정보센터의 현행 별표 원본 | 57 | `data/annex/원본/{work,review}/` |
| 무인비행장치 현행 규정의 별표 원본 | 7 | `data/annex/reg12/원본/` |
| 2024년 연구성과의 원본 한글파일 | 3 | `data/annex/gen/draftUav/` |
| 본문 글로 새로 지은 신설 별표·별지 | 36 | `data/annex/gen/{자리}/` |

```bash
python scripts/fetch_annex_files.py   # 법령정보센터 원본을 곁에 받아 둔다
```

## 본문 속 표·수식 (그림 → XML)

국가법령정보센터 본문은 표와 수식을 **이미지**로 넣어 두어 (`<img id="151295823">`)
검색도 안 되고 고칠 수도 없습니다. 원본 HWPX 에는 진짜 표 객체와 수식 스크립트가 있으므로
그것을 XML 로 바꿔 함께 배포합니다.

```bash
python scripts/genobjects.py "관련규정/공공측량작업규정/공공측량 작업규정.2025.04.23_수식수정.오류표시.hwpx" reg01
```

- 표 → `<table>/<row>/<cell>` — 병합(colspan·rowspan)과 머리행을 그대로 옮깁니다
- 수식 → `<equation>` — 한글 수식 원본 스크립트 · 읽을 수 있는 형태 · LaTeX 세 가지
- 짝짓기는 **조 단위 순서**로 합니다. HWPX 를 문서 순서대로 훑으며 `제N조` 를 따라가고,
  그 조 안에서 나온 차례대로 본문의 `<img id>` 와 하나씩 맞춥니다.
- **쪼개진 수식은 하나로 모읍니다.** 한글은 수식 하나를 여러 조각으로 나누어 좌표로 나란히
  놓기도 합니다(제57조 — `[ΔN;ΔE;ΔU]` + `=` + `[행렬][ΔX;ΔY;ΔZ]`). 국가법령정보센터가 그 셋을
  그림 하나로 찍었으므로 여기서도 하나로 봅니다. 글자처럼 흐르는 조각(`treatAsChar="1"`)은
  저마다 딴 수식이므로 묶지 않습니다.

### 수식은 원문 꼴로 그립니다

한글 수식 스크립트를 **MathML** 로 옮겨 브라우저가 진짜 수식으로 그립니다
([js/core/eqmath.js](js/core/eqmath.js) · 딸린 라이브러리 없음).

| 한글 수식 | 그리는 것 |
|---|---|
| `LEFT [ … RIGHT ]` · `LEFT \| … RIGHT \|` | 줄 수에 맞춰 키운 괄호·절댓값 |
| `eqalign{ a # b # c }` | 줄을 쌓습니다 (행렬·열벡터) |
| `{a} over {b}` · `sqrt{a}` | 분수·근호 |
| `_{…}` `^{…}` | 아래·위 첨자 |
| `TRIANGLE` `SIGMA` `lambda` | Δ · Σ · λ (대문자로 쓴 낱말은 대문자로) |
| 백틱 ` ``` ` | 자간 — 원문의 칸 맞춤을 살립니다 |

마지막 줄이 핵심입니다. 한글 수식에는 **행렬의 열을 나누는 표시가 없습니다.** 글쓴이가 백틱을
여러 개 넣어 눈으로 칸을 맞추어 두었으므로, 그 개수를 너비로 옮기면 원문과 같은 자리에 섭니다.
바꾸지 못한 수식은 예전처럼 글로 보이고, `수식 원본` 을 펴면 글·LaTeX·한글 스크립트를 함께 봅니다.
- **원문 자리 그대로** 그려집니다. 본문 글 사이 `<img>` 가 있던 위치에 표·수식이 끼워집니다.
- 개정안 본문은 미리보기가 기본이고, 라벨 옆 **[고치기]** 로 글자 편집으로 바꿉니다.
- 표가 칸보다 넓으면 줄바꿈을 풀고 글자를 줄여 폭에 맞춥니다.
  그래도 넘치면 **[크게 보기]** 로 전체 폭 덮개 화면에 펼칩니다. 창 폭이 바뀌면 다시 맞춥니다.
- 항목마다 **XML** 을 내려받을 수 있습니다.
- **부호 수정** — 허용오차·확률오차는 `기준값 ± 비례항` 이 옳은데 원문 표에는
  `20mm + 4ppm · D` · `10cm + 2cm√N` 처럼 ＋ 로 적혀 한쪽으로만 벌어지는 것처럼 읽힙니다.
  같은 규정 안에서도 `±(5mm + 1PPM×D)` 처럼 부호를 붙여 적은 표가 있어 표기가 엇갈립니다.
  비례항 앞의 부호를 **±** 로 바로잡았습니다(17곳). 걸린 조문(현행 제27·28·96조)에는
  변경 사유 **`부호 수정`** 이 달리고 상태가 `수정` 이 됩니다.

현행 공공측량 작업규정 기준으로 **75곳 중 67곳**(표 55 · 수식 12)이 바뀌었습니다.
남은 8곳(제185·186·188조)은 배포본 HWPX 에 대응하는 객체가 없어 그림으로 남습니다.

3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/` 하나로 엽니다.
   개정 대상 세 규정은 그 화면 안 트리에 나란히 있습니다 (예전의 `review/` · `uav/` 주소는 없어졌습니다).

`.nojekyll` 은 포함되어 있습니다(없으면 일부 자원이 404).
HTTPS 환경이라 파일 저장 기능이 로컬 `file://` 보다 오히려 잘 동작합니다.

> **GitHub Pages 는 저장소가 비공개여도 사이트는 공개됩니다** (무료 플랜 기준).
> 그래서 이 저장소에는 **앱과 공개된 현행 규정 데이터만** 넣습니다.
> 개정안(`.pmproj`)과 내보낸 비교표는 `.gitignore` 로 제외되어 있으니 그대로 두십시오.
> 작업 내용은 서버로 가지 않고 각자 PC 에만 남습니다.

접근 통제가 필요하면 GitHub Pages 대신 기관 웹서버(IIS·nginx)에 같은 파일을 복사하면 됩니다.

## 데이터 출처와 라이선스

- `data/*.json` — 국가법령정보센터(law.go.kr) 공개 API 로 2026. 8. 12. 기준 현행 조문을 받아
  편·장·절·조 트리로 변환한 것입니다. 원 저작물은 각 소관 기관에 있습니다.
  재생성: `python scripts/gendata.py`
- **법제처에서 내려받은 고시 원문 파일이 있으면 그것을 현행 조문으로 씁니다.**
  공개 API 는 조문을 한 줄로 주어 항·호의 줄바꿈이 사라지고 본문 그림도 빠지지만,
  내려받기 파일(이름은 `.hwp`, 속은 HWPML 2.1 XML)에는 둘 다 그대로 들어 있습니다.
  갈아 끼우기: `python scripts/genhwpml.py <규정id> "<원문파일>"`
  (`--dry` 를 붙이면 고치지 않고 지금 자료와 견주기만 합니다.
  글자가 달라지지 않았는지 대조 결과를 함께 보여 줍니다.)
  적용한 규정에는 `textSource` 가 붙고, 참조규정 창 머리에 **본문 출처**로 보입니다.

  | 규정 | 원문 파일 | 대조 |
  |---|---|---|
  | `reg12` 무인비행장치 측량 작업규정 | `관련규정\하위규정\무인비행장치 측량 작업규정(…제2020-5670호)(20201230).hwp` | 40조 모두 글자 같음 · 줄 얼개 10조 되살림 · 본문 그림 1개 |

  옛 HWP 이진 파일(관보 원본 등)도 같은 스크립트로 견줄 수 있습니다 —
  `hwp5.py` 로 글자만 읽습니다(그림은 꺼내지 않습니다).
- **별표를 손에 있는 원본 폴더로 갖추려면** `scripts/genannexlocal.py` 를 씁니다.
  `genannex.py`·`genannexxml.py` 는 국가법령정보센터에서 받아 오지만, 이쪽은 연구
  자료로 받아 둔 폴더를 그대로 씁니다. 파일 이름의 `[별표 3]` 을 규정의 별표 목록과
  짝지어 세 가지를 한꺼번에 만듭니다.

  | | 자리 |
  |---|---|
  | 미리보기 (PDF → 쪽 그림) | `data/annex/<규정id>/<별표N>_<쪽>.webp` |
  | 원본 파일 (앱에서 내려받기) | `data/annex/<규정id>/원본/<별표N>.hwp` · `.pdf` |
  | 서식 표 XML | `data/objects/<규정id>/annex/<별표N>.xml` |

  원본을 앱 안에 두면 `annexRef.hwp`·`annexRef.pdf` 가 그 파일을 가리키고, 법제처
  주소는 `annexRef.source` 에 남습니다. 표가 아니라 그림으로 된 별표는 HWP 안의
  그림을 꺼내 XML 에 `<image>` 로 싣습니다.

  ```bash
  python scripts/genannexlocal.py reg12 "..\관련규정\무인비행장치 측량 작업규정개정관련\2020.무인비행장치 측량 작업규정"
  ```

  갈래별로 권리자가 다르므로 저장소 뿌리의 [`LICENSE`](LICENSE) 를 함께 보십시오 —

- **저장이 막히면 자동으로 내려받기로 전환됩니다.** 파일에 직접 덮어쓰려면
  Chrome·Edge 에서 `실행.bat` 으로 연 탭을 쓰고, 쓰기 권한 요청에 허용을 눌러야 합니다.
  다른 창 안에 끼워진(iframe) 미리보기나 시스템 폴더에서는 덮어쓰기가 차단됩니다.
  이 경우에도 파일은 내려받기 폴더에 남으므로 작업 내용이 사라지지 않습니다.
- Firefox·Safari 에서는 저장이 항상 **다운로드 방식**으로 동작합니다(덮어쓰기 불가).
- 조문 본문의 항·호는 원문 텍스트를 그대로 사용하며, 표·수식은 텍스트로 평탄화되어 있습니다.
