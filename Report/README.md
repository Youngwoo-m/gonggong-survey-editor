# 개정사유서 원고

개정사유서의 일곱 절 가운데 **개정 목적ㆍ배경ㆍ기대 효과ㆍ종합 의견**은 줄글이라
개정안 자료(`data\draft*.json`)에서 뽑아낼 수 없습니다. 그것을 사람이 쓰는 자리가
여기입니다.

```
원고/무인비행장치_개정사유서.md
원고/성과심사_개정사유서.md
원고/작업규정_개정사유서.md
출력/<규정 이름> 개정사유서.hwpx · .pdf
scripts/build_from_form.py
```

## 짓는 법

```
python Report\scripts\build_from_form.py 원고\작업규정_개정사유서.md
python Report\scripts\build_from_form.py 원고\작업규정_개정사유서.md --pdf
```

양식(`Form\03.개정사유서\[양식] 작업규정 개정안_개정사유서.hwpx`)을 그대로 열어
글자만 갈아 끼웁니다. 글꼴ㆍ쪽 설정ㆍ표 테두리가 한 치도 어긋나지 아니합니다.

## 원고의 짜임

양식은 일곱 절이며, **문단 수가 정해져 있습니다.**

| 절 | 짜임 |
|---|---|
| 1. 개정 목적 | 문단 둘 |
| 2. 개정 배경 및 필요성 | 가.~아. 여덟 갈래, 갈래마다 문단 둘 · 그다음 표 (3열) |
| 3. 주요 개정 내용 | 표 (2열) |
| 4. 조항별 개정 사유 | 표 (3열) |
| 5. 별표 개정 및 신설 사유 | 표 (4열) |
| 6. 기대 효과 | 불릿 다섯 |
| 7. 종합 의견 | 문단 둘 |

**표의 행 수는 마음대로 늘려도 됩니다.** `fit_tables` 가 양식의 표를 원고에
맞추어 늘리거나 줄입니다(마지막 자료 행을 본으로 삼아 찍어 내므로 폭ㆍ병합ㆍ
여백이 그대로입니다). 문단 수가 어긋나면 아무것도 쓰지 아니하고 멈춥니다 —
한 자리라도 밀리면 엉뚱한 칸에 글이 들어가기 때문입니다.

## 원고가 있으면 그것을 씁니다

`scripts\genreport_hwpx.py` 는 보고서 한 벌을 지을 때 `출력\` 을 먼저 봅니다.

* `<규정 이름> 개정사유서_N판.hwpx` — 그 판을 위해 따로 쓴 원고
* `<규정 이름> 개정사유서.hwpx` — 통짜 원고. **마지막 판에만** 씁니다

둘 다 없으면 `scripts\formdocs.py` 가 자료에서 지어 냅니다(조문 사유의
`[이익]`ㆍ`[예상 반론]` 을 모아 6ㆍ7절까지 줄글로 짓습니다).

`scripts\weekly_set.py` 의 지문도 이 원고를 함께 봅니다 — 그러지 아니하면 원고를
고쳐도 자료가 그대로라 하여 넘어가고 꾸러미에 옛 사유서가 남습니다.

## 없는 말은 짓지 아니합니다

숫자와 조ㆍ별표 이름은 모두 개정안 자료에서 세어 확인한 것입니다. 원고 머리의
주석에 무엇을 언제 세었는지 적어 두었습니다. 자료를 고친 뒤에는 그 숫자를 다시
세어 원고를 맞추십시오.
